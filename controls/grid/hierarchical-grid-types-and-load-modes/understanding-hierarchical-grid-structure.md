# Understanding Hierarchical Grid Structure

There are two general steps to implement a hierarchical grid:

1. **Design the hierarchy** In this step, using the designer or code-behind you should specify the structure of the hierarchical tables. This is related to populating the collection of **DetailTables** of RadGrid **MasterTableView** and the corresponding columns. It is important that this step is completed before Telerik RadGrid is bound to any data. For example the grid can have a similar structure:
    - MasterTableView
        - DetailTable(0)
            - DetailTable(0, 0)

    Each detail table, including the **MasterTableView**, is a **GridTableView** control. At runtime, each control is represented by an HTML table object. The table has **RenderColumns**, **Columns**, and **AutoGeneratedColumns** collections for configuring styles, group expressions, and sort expressions. See [Getting familiar with the server-side API]({%slug grid/server-side-programming/overview%}) for more information.

    The whole structure of RadGrid and its detail tables is saved in the **ViewState**. Therefore, if you build a grid programmatically, you can safely do this in **PageInit** or **Page_Load** (see [Programmatic grid creation]({%slug grid/create-radgrid/creating-a-radgrid-programmatically%})). For an example of defining groups in code-behind, see [Programmatically defining group expressions]({%slug grid/functionality/grouping/group-by-expressions/programmatic-definition%}).

1. During runtime (when data-binding) Telerik RadGrid builds special structure of items corresponding to the structure of the detail tables. For each item in the master table a new control (**GridTableView**) will be created and will be assigned as a child of the master item. This control will be a copy of the corresponding table - that should be **DetailTable(0)**. Hence, if you have 3 items in the **MasterTableView** in the second level of hierarchy the grid will look like this:
    - MasterTableView
    + Item(0)
        + DetailTable0(copy 0)
    + Item(1)
        + DetailTable0 (copy 1)
    + Item(2)
        + DetailTable0 (copy 2)

    Here, **Item(0)** is a parent item for **DetailTable(0)**. You can obtain its instance through the **GridTableView.ParentItem** property. This example has a third hierarchy level because each item in a copy of **DetailTable(0)** has a detail table that is a copy of **DetailTable(0, 0)**.

    For example, let's say that the copy of DetailTable(0) with index 0 has 2 items:
    + DetailTable0 (copy 0)
    + Item(0)
        + DetailTable(0, 0) (copy 0)
    + Item(1)
        + DetailTable(0, 0) (copy 1)

    Bind each copy of a detail table to populate its items. RadGrid gives you full control over this process: filter or select only the records that correspond to each detail table. RadGrid restricts only when this occurs, either through [declarative hierarchy relations](https://demos.telerik.com/aspnet-ajax/grid/examples/hierarchy/declarative-relations/defaultcs.aspx) or the [DetailTableDataBind event](https://demos.telerik.com/aspnet-ajax/grid/examples/data-binding/programmatic-hierarchy/defaultcs.aspx).

    If you choose the second approach, RadGrid fires **DetailTableDataBind** for each **DetailTable** that is about to be bound. This behavior depends on the **HierarchyLoadMode** property of the corresponding **GridTableView**:
    * **HierarchyLoadMode** is **ServerBind** - the **DetailTableDataBind** event will be fired immediately after the corresponding parent item is bound.
    * **HierarchyLoadMode** is **ServerOnDemand** - the detail table will be bound as soon as its parent item is expanded.

    In the **DetailTableDataBind** event handler, determine which detail table is about to be bound by using its **DataMember** property. Assign a unique value to this property in step 1.
